6.3.3 Diagramme de séquence d'application du Sprint 2

Pour ce sprint, nous représentons le diagramme de séquence d'application du cas d'utilisation « Passer une commande ». Le système intègre un mécanisme Escrow (séquestre) : le client paie, les fonds sont bloqués, puis libérés progressivement au tailleur à chaque étape validée par photo preuve.

CommandePage (modèle + tailleur) Note over CMD: Formulaire : tissu, couleur, notes Note over CMD: Affichage : prix, commission 15%, part tailleur 85% Client->>CMD: 3: Confirmer la commande statut_commande (log initial) BD-->>CTRL_C: 3.1.3: Commande créée (id) CTRL_C-->>CMD: 3.2: Confirmation JSON CMD-->>Client: 4: "Commande envoyée — en attente d'acceptation" Note over Tailleur: Le tailleur reçoit la commande Tailleur->>CMD: 5: Accepter la commande CMD->>CTRL_C: 5.1: PATCH /commandes/:id/statut (statut='acceptee') CTRL_C->>BD: 5.1.1: UPDATE commande SET statut='acceptee'
